# AI Context Collection（边界）

## 产品结论

```text
Lancer = Runtime + 现场整理
Lancer 本身不接模型、不做第二个 AI Coder
产出 = 标准 Markdown，交给外部 AI Coder（Cursor 等）
```

## 原则

```text
日志对人是 Runtime
日志对 AI 是 Context / Text（Markdown 文件）
```

AI 不需要：

- 跨工具 `LogSession` / `LogProvider` 领域模型
- 整份 managed-log 灌进 LLM

AI 需要：

- **有边界**的日志摘录
- **少量元信息**（集群 / Pod / 容器 / 时间）
- 固定结构的 **Markdown**，方便粘贴或拖进 AI Coder

## 标准产物：`lancer-ai-context-*.md`

实现：`src/capabilities/kubernetes/logs/ai-context-md.ts` → `buildAiContextMarkdown`。

UI：

- **复制**（Copy）：写入剪贴板
- **下载**（FileDown）：保存 `.md` 文件

形状（稳定契约，改字段需同步文档）：

```markdown
# Lancer AI Context

> Generated by Lancer for an external AI Coder. Lancer itself does not run a model.

## Meta

| Field | Value |
| --- | --- |
| cluster | … |
| source | ns/pod/container |
| … | … |
| focusLine | 1234 |
| searchQuery | … |
| timeRange | … |

## Logs

```log
  1230  2026-10-08 10:31:22  [INFO]  …
  1234  2026-10-08 10:31:24  [ERROR]  … ◀
```

## Ask (for AI Coder)

Based on the log excerpt above:
1. What is the most likely root cause?
2. Which local source files should I inspect?
3. What concrete code/config changes would fix it?
```

采集范围：以 focus 行（搜索命中或视口中部）为中心，默认前后各 **50** 行；正文来自当前 Read Window，不经 Universal Log Aggregate。

## 明确不做

- Lancer 内嵌 Chat / 调模型
- 为了 AI 在本机扫任意工程 / 再造 AI Coder
- GitLab 拉代码作为主路径（可选以后「补证据」，非本刀）

## 以后可增强（仍不接模型）

- 包里附带 Jenkins 构建号 / commit（若已能解析）
- Docker / Jenkins Console 各自采成**同一套 MD 章节结构**
- 「一键打开 AI Coder」仅深链/剪贴板，不在进程内跑模型

## 验收

- PR 不得引入「为了 AI」的跨工具 Log 领域层
- 导出物是 **Markdown 字符串**；输入是选区/命中行 + 扁平元信息
